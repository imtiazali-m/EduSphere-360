EduSphere 360 — Remove the one-time setup secret from online registration

WHAT THIS PATCH DOES
- Removes the setup-secret field from the online setup screen.
- Prevents public first-owner registration through the website.
- Shows a simple notice directing the project owner to create the first cloud user in their own Supabase dashboard.
- Keeps the offline local registration form available.
- Keeps normal Supabase login, the authenticated create-user function, roles, and database RLS/security policies.
- Includes SQL to attach the first Supabase Auth user to the institution as owner.

INSTALL THE PATCH
1. Extract this ZIP.
2. In your existing project folder, replace these three files with the files from the patch:
   - src/components/AuthScreens.tsx
   - src/lib/auth.ts
   - src/context/AuthContext.tsx
3. Save all files. Vite should hot-reload; if not, restart npm run dev.

CREATE THE FIRST ONLINE OWNER
1. Open the correct Supabase project: osqhgsqrqhollxxtwrgy.
2. Go to Authentication > Users > Add user. Create the owner account or send an invitation.
3. If you send an invitation, accept it and complete the account setup before logging in.
4. Copy the user's UUID from the Authentication > Users list.
5. Open MANUAL_FIRST_ADMIN_SETUP.sql and replace:
   - PASTE_AUTH_USER_UUID_HERE
   - YOUR FULL NAME
   - YOUR EMAIL ADDRESS
   - EduSphere Academy (if you want another institution name)
   - school (choose school, college, university, or multi_institution)
6. In Supabase SQL Editor, first check whether institutions already exist:
      select id, name, institution_type from public.institutions;
   If this returns any rows, do NOT run the setup script; contact the project owner to link the existing records instead.
7. If it returns zero rows, paste the completed MANUAL_FIRST_ADMIN_SETUP.sql into SQL Editor and run it once.
8. In EduSphere 360, select Online > Login > Administrator and sign in with the Auth user's email/password.

AFTER THE OWNER CAN SIGN IN
The bootstrap-admin function and EDU_BOOTSTRAP_SECRET are no longer needed. You can remove them from Supabase:
   npx.cmd supabase functions delete bootstrap-admin --project-ref osqhgsqrqhollxxtwrgy --yes
   npx.cmd supabase secrets unset EDU_BOOTSTRAP_SECRET --project-ref osqhgsqrqhollxxtwrgy --yes
Do this only after confirming that the owner can sign in.

DO NOT REMOVE
- Supabase Auth.
- The create-user Edge Function.
- Row Level Security policies.
- The Supabase publishable key from .env.local (it is designed for public browser use when RLS is correctly configured).
Never put a Supabase secret/service-role key in browser code or .env.local.
